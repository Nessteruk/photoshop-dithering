# Architecture

Dithering is a Photoshop UXP panel (plain JavaScript, bundled by webpack together with the Spectrum Web Components wrappers, which are the only dependencies). The code is split so that the dithering algorithms and the settings can be changed without touching Photoshop-specific code.

## Layout

```
main.js                  plugin entry point: registers the panel
index.html, styles.css   panel shell (wrapped in sp-theme), and the layout styles
webpack.config.mjs       bundles main.js and the Spectrum Web Components into dist/main.js
dist/                    build output (not committed)
manifest.json            UXP manifest (v5, Photoshop 26+, SWC enabled)
src/
  core/                  pure code, no Photoshop, tested with Node
    schema.js            common settings (cell size, contrast, brightness, levels, color mode)
    settings.js          builds the full parameter list, defaults, validation
    links.js             stored links (Dithering layer id to settings): parse, serialize, prune
    xmp.js               reads and writes one custom field in an XMP packet
    history-watch.js     tells which history events are user changes (new state, not the plugin's own, not an undo)
    name-registry.js     remembers the settings last used under a layer name, to give them to a layer pasted into another document
    link-history.js      keeps the links (settings of every Dithering layer) as they were at each history state
    layer-tree.js        finds layers, the layers above or below one, and the next free layer name
    errors.js            error codes shown to the user
  algorithms/            pluggable dithering algorithms (pure code)
    index.js             list of algorithms, in the order of the panel's list
    diffusion.js         Floyd-Steinberg, Atkinson, Stucki, Sierra Lite
    bayer.js             Bayer ordered dither (2x2, 4x4, 8x8, 16x16)
    blue-noise.js        blue noise ordered dither
    halftone.js          halftone screens (square, hexagon, radial, line, circle), drawn at output resolution
    blue-noise-data.js   generated threshold tile (tools/make-blue-noise.js)
    threshold-map.js     shared multi-level ordered dithering with a threshold tile
  engine/                rendering pipeline (pure code)
    planes.js            RGBA to one gray plane or three color planes, and alpha
    adjust.js            contrast and brightness
    compose.js           levels to RGBA, nearest-neighbour upscale
    render.js            runs the whole pipeline
  photoshop/             everything that calls the Photoshop API
    effect.js            reads pixels, creates and updates the Dithering layer
    document-data.js     stores the links in the document's XMP metadata
    source.js            reads the active layer and finds its stored link
    auto-update.js       listens to history events: automatic update, undo and redo of a change with its render
  ui/                    panel behavior
    swc.js               imports (registers) the Spectrum Web Components the panel uses
    components.js        the interface elements (action button, action group, checkbox, text field, slider, select, divider, section): the only place that builds them
    controls.js          one builder per parameter type, on top of components.js
    panel.js             builds the panel from the schema, handles state
    render-controller.js add, update, convert and automatic update
    presets-panel.js     user presets: save, delete, import, export (none is built in)
    confirm.js           confirmation dialog
    theme.js             detects the Photoshop theme and sets the color of sp-theme
    dom.js               small DOM helpers
  locales/               one file per language (en.js, fr.js)
  i18n.js                language detection and t()
  storage.js             persistence in the plugin's local storage
  registry.js            name-registry.js persisted in that storage
icons/                   generated by tools/make-icons.js
tools/                   development scripts (icons, blue noise tile, .ccx package)
THIRD-PARTY-NOTICES.md   licenses of the packages bundled in dist/main.js
test/                    node:test suites
```

Only `src/photoshop` and `src/ui` need Photoshop. Everything else runs in Node, so `npm test` works without Photoshop.

## Settings are declarative

A setting is an object in a schema array:

```js
{ key: "cellSize", type: "slider", section: "pattern", min: 1, max: 32, step: 1, unit: " px", default: 2 }
```

Supported types:

| type | fields |
|---|---|
| `slider` | `min`, `max`, `step`, `unit`, optional `decimals` |
| `choice` | `options: [{ value }]`, shown as a row of text buttons |
| `select` | `options: [{ value }]`, shown as a drop-down list |
| `checkbox` | none |
| `text` | optional `maxLength` |

Optional fields: `order` (position inside the section, algorithm settings come first by default, the common ones use 10, 20, 30) and `hideWhen: { key, values }` (hides the setting while another setting has one of the values). Every setting has `key`, `type`, `section` (`pattern` or `colors`, the second one holding the levels and the color mode) and `default`. The panel builds its controls from these entries; `settings.js` derives the defaults and the validation (`sanitize`) from them. The algorithm itself is chosen in a drop-down list built from `ALGORITHMS`.

## Add a setting

1. Add an entry to `COMMON_PARAMS` in `src/core/schema.js` (shared by all algorithms), or to the `params` of one algorithm.
2. Add its texts to every file in `src/locales/`: `param.<key>`, and `option.<key>.<value>` for each option of a `choice`.
3. Run `npm test`. The tests fail if a key is duplicated or a translation is missing.

No HTML or CSS change is needed. Keys must be unique across all algorithms. A setting declared by an algorithm is only shown while that algorithm is selected.

## Add a field type

A type is made of three things, and a test fails if one is missing:

1. a sanitizer in `VALUE_TYPES` in `src/core/settings.js` (a pure function that returns a valid value);
2. a builder in `BUILDERS` in `src/ui/controls.js`, returning `{ element, update(settings) }` and calling `api.set(key, value)` when the user changes the value;
3. if it needs a new element, a function in `src/ui/components.js` and its rules in `styles.css`.

All the styles live in `styles.css`: scripts only choose class names (a test rejects inline `.style`, and a class without a rule). The file starts with the shared values, so nothing is repeated below: sizes and spacing on `html` (`--text-size`, `--space-*`), one palette per Photoshop theme on `sp-theme[data-theme=...]` (field background, borders, hover, selected, disabled), and one block of `--mod-*` properties on `sp-theme` that tunes the Spectrum components from those variables. To restyle the panel, change a variable; to style a new component, add its `--mod-*` lines to that block.

## Presets

The panel ships with no preset. The user saves the current settings under a name, and can import or export them as a JSON file (`dithering-presets`). Changing any setting puts the list back on *None*.

## Interface components

The panel is built with Spectrum Web Components (SWC) through Adobe's UXP wrappers, all in size S:

| Element | Component |
|---|---|
| Buttons | `sp-action-button` |
| Exclusive choices (color mode, Bayer matrix, user presets) | `sp-action-group` with `selects="single"` |
| Checkboxes | `sp-checkbox` |
| Text fields and the value of a slider | `sp-textfield` |
| Section separators | `sp-divider` |
| Sliders | `sp-slider` (built into UXP: it has no SWC wrapper) |
| Drop-down lists | HTML `<select>` (no SWC picker) |
| Collapsible sections | our own `section` in `components.js` |

To add a component: install its `@swc-uxp-wrappers/<name>` at the exact version of the others, import its `sp-<name>.js` in `src/ui/swc.js` (a test checks it), then build it in `components.js`. Colors come only from the `--spectrum-global-color-gray-*` tokens defined by `sp-theme`. The theme color follows Photoshop's theme: `theme.js` maps Darkest and Dark to Spectrum `dark`, Light to `light` and Lightest to `lightest`; change the table `SPECTRUM_COLOR` there to retune it.

## Add an algorithm

1. Create `src/algorithms/<name>.js`:

   ```js
   module.exports = {
     id: "myDither",
     params: [],
     process(input, settings) {
       const { width, height, values, levelCount } = input;
       const levels = new Uint8Array(width * height);
       return { width, height, levels };
     }
   };
   ```

2. Register it in `src/algorithms/index.js`. The order of the list is the order of the drop-down.
3. Add `algorithm.<id>` and the texts of its parameters to every locale.

### Processing contract

```
process(input, settings) -> output
// input:  { width, height, values, levelCount }
//         values is a Uint8ClampedArray of one channel, 0-255 (255 is the lightest)
//         levelCount is the number of output levels, 2 to 16
// output: { width, height, levels }
//         levels is a Uint8Array of level indices, 0 (darkest) to levelCount - 1 (lightest)
```

The function is pure: no Photoshop calls, no globals, so it can be unit tested with Node. It works on the reduced grid (one pixel per dither cell), so the cost depends on the grid, not on the canvas size. In gray mode it runs once on the luminance, in color mode once per red, green and blue channel (the same threshold tile is used for the three channels). Contrast and brightness are applied before it runs, and level to color mapping and upscaling after (level `i` becomes `round(i * 255 / (levelCount - 1))`). `npm test` checks that every registered algorithm keeps white and black for any number of levels, reproduces the tone of flat grays and uses only the two levels around a gray.

Algorithms that draw shapes at the final resolution (halftone) set `atOutputResolution: true`. They still receive the reduced image in `values` (`width` x `height`) and also `outputWidth`, `outputHeight`, `channel` and `channelCount`, and must return `levels` of `outputWidth` x `outputHeight`. They may also define `readScale(settings)`, the factor by which the layer is reduced after reading it (the default is `cellSize`).

### Algorithms

- **Error diffusion** (`diffusion.js`): the kernels are tables of `[dx, dy, weight]` with a divisor. Each pixel goes to the nearest of the output levels, the error is kept in floats and rows are scanned in serpentine order. Atkinson keeps 6/8 of the error, the others all of it.
- **Bayer** (`bayer.js`): the matrix is built by replacing each cell with four cells (4 × value plus 0, 2, 3, 1). With several levels, a pixel takes the level just above its tone when the fractional part is above `(rank + 0.5) / n²` (`threshold-map.js`).
- **Halftone** (`halftone.js`): the element box has a side of *Size* and the pitch is *Size + Spacing*. Inside each box, a spot function (square, circle, hexagon) grows with the tone of the cell, with thresholds built so that the covered area is proportional to the tone, so that at spacing 0 black fills the cell. The tone is sampled at the cell center. Lattices: square (square and circle), hexagonal with offset rows (hexagon), parallel lines whose thickness follows the tone (line, sampled continuously along the line) and concentric rings of `round(2πk)` round elements around the layer center (radial). The lattice turns around the layer center by *Angle*; in color mode the *Channel offset* setting (0 by default) adds that angle to the green channel and twice that angle to the blue channel. Edges are hard with 2 levels, and with more levels the coverage of each pixel is estimated by supersampling and quantized to the levels. At small sizes the tone is limited by the pixel grid: a 10 px element can only have an even width, so a few tone steps are visible.
- **Blue noise** (`blue-noise.js`): same threshold rule with a 128 x 128 tile generated by `node tools/make-blue-noise.js` (void-and-cluster). Each of the 256 threshold levels appears the same number of times and the tile repeats without seams.

## Rendering flow

1. *Add a Dithering layer* creates a pixel layer named Dithering Render above the selected layer (`photoshop/effect.js`), with the last settings used. It behaves like an adjustment layer, but its content is pixels that the plugin recomputes. The layer is red (color label) and its pixels and position are locked; they are unlocked for the time of each update.
2. What the layer reads depends on its state, checked at every update. If it is a clipping mask (`Layer.isClippingMask`), it reads the layer it is clipped to (the first layer below it that is not clipped). Otherwise it reads everything visible below it: the layers above it (and itself) are hidden for the time of the read, inside the modal state, then restored. With *Include hidden layers* (a setting saved with the layer), the hidden layers below it, groups and their children included, are shown for the read too.
3. `getPixels` reads the layer at full resolution as 8-bit RGB, and `engine/downscale.js` reduces it by the algorithm's read scale (`cellSize` by default) with an alpha-weighted box average.
4. `engine/render.js` splits the pixels into planes, applies contrast and brightness, runs the algorithm on each plane and builds the image, upscaled back to the layer size with nearest-neighbour sampling (or drawn at the final size for halftone).
5. `putPixels` writes the result into the layer, and the settings are saved in the document, in a single history state (`executeAsModal` and `suspendHistory`).
6. The settings of every Dithering layer are stored in the document's XMP metadata, in one `dith:links` field (`core/links.js`, `photoshop/document-data.js`), so they survive saving and closing. Selecting a Dithering layer reloads its settings into the panel; on a normal layer the panel only shows the state and the *Add* button. *Convert to normal layer* forgets the link, unlocks the layer, removes its color and renames it *Layer N* with the smallest free number. With *Live preview* on, changing a setting re-renders the layer after a short delay; otherwise use *Update*.
7. *Update automatically* (a saved setting, on by default): `photoshop/auto-update.js` listens to `historyStateChanged`; `core/history-watch.js` classifies each event (user change, own state, undo/redo, or landing inside a change + render group), and after a short delay `effect.refreshDocument` recomputes the Dithering layers of the active document, lowest first, in one history state. Undo and redo step over such a group in one go (`activeHistoryState`). After an undo or redo, `photoshop/link-history.js` gives back the links recorded for the state reached, so the stored settings and the panel follow the layer (including undoing or redoing a conversion).

Known limits: 32-bit documents are not supported. Live preview adds one history state per update. A Dithering layer inside a group reads everything below it in the whole document, not only inside the group.

## Add a language

Copy `src/locales/en.js` to `src/locales/<code>.js`, translate the values, and register it in `src/i18n.js`. A test checks that every locale defines the same keys.

## UXP constraints that shape the code

See `docs/DECISIONS.md` (in French) for the details. In short: only Spectrum components are used, because a hand-drawn border on a `div` is blurred on half pixels and a native `input` ignores its text color; the text size is set on each kind of element, as it is not inherited; the built-in `sp-slider` cannot be restyled, so the slider keeps a fixed rail height and offset.

`require` cannot resolve a folder: write `require("../algorithms/index")`, not `require("../algorithms")`. A test enforces this.

Load errors are written to `%APPDATA%\Adobe\Adobe Photoshop <version>\Logs\UXPLogs_*.log` on Windows.

## Tests

```
npm test
```

Uses Node's built-in test runner (Node 22 or later), no installation needed. The suites cover the schema, validation, translations, the algorithms, the engine, and consistency between `index.html`, `styles.css` and the scripts.
